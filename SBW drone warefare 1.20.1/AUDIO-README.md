# Explosion Audio 1.0.9-audio.2

The four user-supplied MP3 recordings provide all new explosion layers. Each distance range has its own source. This bank contains no vanilla audio or rejected synthesized audio. The user reports Pixabay as the source; individual URLs and authors have not been supplied. See `sounds/explosion_audio/license.txt` and `manifest.json` for terms, source hashes and processing details. This audio is governed by the stated third-party terms, not automatically by the project's code license.

Client settings: `config/sbwdroneconfig-explosion-audio.toml`, section `[explosionAudio]`. Defaults and ranges: `volume=0.65` (0–1), `maxDistance=1024.0` (16–2048 blocks), `distanceDelay=true`, `propagationSpeed=343.0` (50–2000 blocks/second), and `maxEffects=8` (1–16). Each effect uses at most two adjacent mono layers, with a maximum of 64 pending events. Volume also respects Minecraft's Master and Blocks volume settings. Existing engine-sound and FPV settings continue to apply to engines.

The actual main camera determines distance, direction and arrival time. During FPV control, this is the drone camera; after exiting, it is the normal player camera. A pending sound wave adjusts its arrival time when the camera moves or changes. A playing source remains at the detonation position, with attenuation calculated from the current camera. Distance layers are selected on arrival and retained for the duration of that sound. Changing worlds or disconnecting clears pending and active custom effects. The server sends one confirmed VFX/audio event containing the dimension and time, never a separate packet for each layer. Damage and VFX do not wait for sound. Audio does not load chunks. Server-side event reception is limited to 2048 blocks. Visibility remains subject to Minecraft's normal render distance and fog.

Profiles: `radius < 6` uses the small bank; `radius >= 6` uses the heavy bank, with intensity derived from the effective radius. Marker profile 0 remains silent. Distance anchors are 0/45/160/420 blocks, with smoothstep interpolation between adjacent layers; effects are silent beyond `maxDistance`. Each layer has three variants at a fixed pitch of 1. The small profile has a shorter envelope and less bass; the heavy profile has its own bass processing and a longer low-frequency echo tail derived from the same recording. Simultaneous groups share volume headroom.

Forge production builds require the annotation processor's refmap. JavaCompile caching is disabled for this task because the MixinGradle version in use does not restore this additional output file. The jar task rejects a JAR without `sbwdroneconfig.refmap.json`. Protocol 22 requires the same addon version on the server and client. See the supplied test results for the dependencies actually tested and the limits of that testing.
